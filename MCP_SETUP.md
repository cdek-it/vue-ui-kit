# Figma MCP: OAuth и локальный сервер

Общий конфиг хранится в `.ai/mcp/mcp.json`, без токенов и личных путей.
Корневого `mcp.json` нет. Конфиг содержит два независимых подключения:

- `figma` — официальный удалённый сервер `https://mcp.figma.com/mcp`, авторизация через OAuth.
- `figma-local` — установленная локально команда `figma-mcp`, авторизация через `FIGMA_TOKEN`.

Выбирайте нужный сервер в клиенте. У них разные инструменты и возможности;
локальный сервер не является копией официального Figma MCP.
Наличие `.ai/mcp/mcp.json` не означает автоматического подключения в каждом IDE.

## Официальный Figma MCP через OAuth

В Codex используйте официальный плагин Figma и войдите в аккаунт при подключении.
Если плагин уже подключён и `whoami` возвращает ваш профиль, повторная настройка
не нужна. Не добавляйте второй экземпляр того же сервера только ради файла проекта:
Codex не импортирует этот JSON автоматически. Личный `FIGMA_TOKEN` этому способу не нужен.

В других поддерживаемых клиентах добавьте HTTP-сервер
`https://mcp.figma.com/mcp` и пройдите OAuth-вход по запросу клиента.
Доступ зависит от поддержки клиента и прав вашего аккаунта в Figma.

[Официальная инструкция Figma](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/)

## Локальный `figma-mcp` через токен

Установите используемый вашей командой сервер `figma-mcp` и убедитесь,
что команда доступна в окружении клиента:

```bash
command -v figma-mcp
```

Для локального сервера с инструментами `get_file`, `get_file_nodes`,
`export_images` и `get_me` нужны scopes `file_content:read` и `current_user:read`.
Права записи не требуются. Другие реализации и версии могут требовать иных scopes.

Создайте personal access token в Figma: Settings → Security → Personal access tokens.
Задайте `FIGMA_TOKEN` в окружении процесса сервера или в поле `env` его
пользовательского конфига. Не записывайте токен в файл проекта.

Если переменная задана в `~/.bashrc`, перезапустите терминал после её обновления.
IDE, запущенная из меню рабочего стола, может не наследовать это окружение:
настройте переменную именно для процесса сервера в клиенте.

Проверяйте реальный запрос `get_me` или чтение доступного файла. Успешная
инициализация MCP и получение списка инструментов сами по себе не проверяют токен.
Ошибка 401 при запросе к Figma означает, что авторизация не прошла.

[Создание personal access token](https://developers.figma.com/docs/rest-api/personal-access-tokens/)
и [список scopes](https://developers.figma.com/docs/rest-api/scopes/).

## JetBrains + GitHub Copilot

Общий JSON использует формат `servers`, который поддерживает GitHub Copilot
в JetBrains. Откройте настройку MCP через инструменты Copilot Chat и перенесите
нужные записи из `.ai/mcp/mcp.json` в пользовательский конфиг клиента.
Сохраните существующие подключения, если они уже есть.

Для ранее настроенного в проекте пользовательского пути
`~/.config/github-copilot/intellij/mcp.json` также используйте записи из общего
конфига. Не перезаписывайте весь файл, если там есть другие серверы или личные настройки.
В клиентах с форматом `mcpServers` перенесите записи в этот раздел вместо `servers`,
сверившись с документацией конкретного клиента.

[Настройка MCP в GitHub Copilot](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/customize-copilot/extend-copilot-with-tools-and-context/extend-copilot-chat-with-mcp?tool=jetbrains)

## Проверка общего конфига

```bash
python3 -m json.tool .ai/mcp/mcp.json >/dev/null
```

OAuth-сессии, personal access tokens и персональные настройки остаются на машине
пользователя. Не коммитьте их в репозиторий и не добавляйте секреты через симлинк
на общий JSON.
